# 微信压缩后的恢复分析（2026-09-29）

本次使用用户提供的同一页面转发前后 JPEG 实测。较大文件1206×1626、68737字节；微信处理后904×1220、37128字节，宽高比例分别0.749585和0.750308。两者均为4:2:0色度采样。原图像及载荷字段不进入仓库，[测量记录](measurements/wechat.json)只保留尺寸、量化表和恢复统计。

## 失败原因与已完成改进

旧解码器可以恢复较大图片，纠错0；微信处理后主色度通道无法形成有效载荷。在正确几何邻域按较大图片真值诊断，硬判决仍约88～100位错误，超过BCH单次t40能力。图像面积足够，minObs仍能达到12，因此降低小图门槛不能解决这个问题。

主通道读取 `B-(R+G)/2`。生成器本来就有与主载波反极性的R/G伴色，压缩后仍留下可用信号；读取 `-(R+G)/2` 后，本例能纠正37位并恢复相同的完整27字节。这是利用已有像素残差，不改变delta、alpha、载荷、tile或编码协议。

JPEG的色度上下采样会改变高频纹理，编码质量系数也不足以描述完整传播链路。libjpeg-turbo文档明确指出平滑色度上采样会降低高频细节锐度，支持把采样与解码方式一起纳入测试；这不代表微信必然使用该库或相同设置。[libjpeg-turbo说明](https://www.libjpeg-turbo.org/About/Performance)

实现包括：

- 先完整运行主通道；只有无有效载荷时尝试伴色。已有TOO_SMALL或ambiguous结论直接保留；luma实验渲染不启用此回退。
- 伴色包含亮度，白框/黑框的亮度台阶可能污染判位。内容矩形外及跨越其边缘的cell不参与伴色信号和导频统计。
- 伴色相位精搜采用x±2/±1/0、y±1/±0.5/0，并按cell周期环绕。这样可以覆盖加框后落到周期边界附近的半像素相位，仍按pilot排名限定候选数。
- CLI增加 `companionRecovery=true/false`。两条通道使用相同的物理观测门槛，不把同一像素的不同颜色特征重复计数；仍验证BCH、CRC、字段合法性与唯一性。

## 实测结果

环境：arm64 macOS26.6.2、release Swift CLI、Pillow11.3.0/numpy2.0.2。下表每项Swift/Python载荷与接受/拒答一致。“再次JPEG”是对用户提供的压缩图进行Pillow派生测试，不冒充微信再次转发。

| 输入 / 后续处理 | 结果 | 纠错位数 | minObs |
|---|---|---:|---:|
| 较大图片，自动搜索 | 主通道恢复 | 0 | 12 |
| 微信压缩图，自动搜索 | 伴色恢复 | 37 | 12 |
| 微信压缩图，已知宽度比例 | 伴色恢复 | 37 | 12 |
| 微信压缩图再JPEG Q92 / 4:2:0 | 伴色恢复 | 38 | 12 |
| 微信压缩图再JPEG Q85或Q76 / 4:2:0 | NO，拒答 | — | — |
| 微信压缩图裁去左右各13、上下各29px | 伴色恢复 | 37 | 12 |
| 微信压缩图加黑框或白框（左17上31右19下23） | 伴色恢复 | 37 | 12 |

本例自动搜索耗时：Python22.606s、Swift5.830s；已知比例时Python0.984s、Swift0.103s，计时范围分别为解码调用与CLI进程，部分阶段与测试并行。回退会增加失败图和弱信号图的搜索成本，不能把已知比例耗时当作默认耗时。

原有六页组合测试42个正样本、2个未知比例样本恢复，6个小裁片拒答；Swift15项、Python10项回归通过。新增公开合成样本专门衰减色度并保留伴色，覆盖再缩放、压缩、黑/灰/白框与备用通道小图拒答；它不是这次用户截图，也不代表微信内部编码器。

复测真实文件（输出只包含统计，临时派生图片会清理）：

```bash
swift build -c release
python3 tools/benchmark_pair.py \
  --original /path/to/original.jpg \
  --compressed /path/to/wechat.jpg \
  --output /private/tmp/pair.json
```

## 进一步提升的优先顺序

下面是待验证的设计方向，不是本次已实现或已证明的成功率提升。

| 方向 | 预期解决的问题 | 约束 / 代价 |
|---|---|---|
| 按局部导频质量选择或融合色度与伴色 | 当前整图回退在文字、照片等强R/G内容背景上可能失效 | 权重应由导频和局部噪声估计决定；两个特征相关，不能重复计算观测数，必须补复杂背景和无水印负样本 |
| 水平/垂直分别拟合比例，再细化相位 | 整数尺寸取整产生的轻微非等比缩放会使长距离cell对齐漂移 | 本例宽高比例确有差异，但已由当前单比例恢复；需独立样本证明新增自由度有效，并限制搜索成本 |
| 调整载波在空间中的分布及重复副本位置 | 缩到0.75后cell只有约24×6像素，色度采样后每cell的纵向样本很少；副本可能遭受相似量化损失 | 更高cell或不同网格相位可能保留更多信号，但会增加tile面积、降低小裁片观测数；属于协议变更，需要重新验收 |
| 导频驱动的局部降噪与软判决 | 把剩余弱信号转成更可靠的位分数，改善接近纠错边界的样本 | 简单纵向锐化在本例仍有80多位错，不能直接上线；更多Chase枚举也不能补回已经丢失的信号 |
| 建立真实客户端转发矩阵 | Pillow同质量参数不能覆盖实际微信缩放、采样和重复编码顺序 | 保留转发前后文件配对，覆盖客户端版本、纯色/文字/照片、重复转发、裁切和边框；指标用全部字段一致率、拒答率、误接受与耗时 |

优先扩大真实配对样本，再验证局部通道选择和独立比例拟合。生成端调整载波或增加幅度应单独做观感与容量评估；当前默认delta4保持不变。此次恢复不等于任意强压缩可恢复，尤其Q85/Q76派生失败样本仍说明信息损失的边界。
