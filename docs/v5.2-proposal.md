# v5.2：自包含紧凑水印、纠错与缩放恢复

状态：实施议案。关联 https://github.com/zylcold/BlindWatermark/issues/4 。本文件中的目标不代表已通过真机或 IM 验收；实现范围和实验结果另行记录。

## 目标与兼容

无后台、无 ML，用系统截图离线恢复 Bug 诊断信息。保留 iOS overlay/render server 路线，不涉及防伪、主动攻击、拍屏、旋转或透视。v4 解码与现有默认编码必须保留；v5.2 首版显式 opt-in，实验通过前不切默认。协议版本与软件发布版本分开，不因本 PR 自动发布 tag/release。

## 冻结的候选协议

207 bit 信息按明确位序打包，Swift/Python 共用 golden vectors：

| 字段 | bit | 约束 |
|---|---:|---|
| version/profile | 4 | 固定 profile 值，拒绝未知值 |
| uid | 32 | UInt32 |
| timestamp | 31 | UTC 2026-01-01 起秒数，拒绝溢出 |
| buildTime | 24 | UTC 2026-01-01 起分钟数，拒绝溢出 |
| page | 42 | 8 字符 base-37 |
| app | 14 | 0...9999 |
| note | 32 | 6 字符 base-37 |
| CRC24 | 24 | 明确多项式、初值、反射、xorout、覆盖位和补位 |
| reserved | 4 | 固定 0，拒绝非零 |

字符表为 abcdefghijklmnopqrstuvwxyz0123456789_。整段 radix-37 编码；明确字序、补位、空值和非法字符规则，拒绝超出 37^N 的值。页面沿用归一化语义，重新实现紧凑字段，不能直接复用最少输出 12 字节的旧 PageNameCodec.encodeBytes。截断页面仅为定位提示，不宣称唯一；构建期可统计碰撞。note 不承诺任意 UTF-8；末尾下划线是否保留必须明确。

采用 binary primitive narrow-sense BCH(255,207)，48 bit 冗余，保证纠正合并后最多 6 bit 错误；固定 GF(256) 本原多项式、生成多项式、系数/位序。第 256 bit 为整体偶校验，定义扩展码验证和距离规则。不要把 Chase 能力宣称为额外保证纠错位数。不得新增第三方依赖。

## 数据层与空间映射

8×8 原始设备像素 block、256×256 tile、512 pair，每 256 bit 码字重复两次，业务极性相反。先保留可验证的映射作为 baseline。固定 permutation 不会减少单个 BCH 码字的错误数量；其目标只能是改善空间覆盖、重复观测相关性与裁剪形状鲁棒性，收益必须实验确认。映射与导频联合设计并版本化。

## 同步导频实验

比较无 pilot、普通 PN 叠加、反极性重复分离三组。优先探索两次业务观测 ±D*b，pilot 同相 P*p：求和增强 pilot、求差增强 data。在理想对齐且增益一致时相互抵消；裁剪丢失一份、128 px 纵向间隔、内容噪声、JPEG 非均匀衰减会破坏理想条件，需降级路径。

模板必须验证二维自相关、次峰、半 tile/倍频歧义和局部裁剪后的相关性。同一 payload 重复造成的 data/pilot 相关偏置不保证随 tile 数增加消失。

不能直接调用现有 paint(alpha: 2) 假设得到纯 chroma pilot：delta 参与预乘 RGBA/alpha，陪色取整会产生亮度残差。优先联合生成单层 tile，保持空间恒定 alpha，记录实际色度幅度和亮度残差；幅度 1/2/3/4 为实验档，不承诺不可见。真实 P3/sRGB、黑白灰和彩色背景与 OLED 可见性仍需人工验收。

## 几何恢复与候选裁决

canonical 快路径（含 v4）→ pilot 多尺度候选 → 局部精搜 → 有预算的无 pilot fallback。首版只实现等比缩放；0.50...1.50 是搜索目标，不是保证成功范围。

相位必须包含当前实现覆盖的 block 内像素位置、左右块奇偶、tile 行列平移；亚像素相位仍是后续实验项。scale 精度根据有效图像跨度与容许像素漂移决定，不能固定 0.001 即认为足够。先廉价几何评分，再少量 BCH，最后有限 Chase；候选数、时间或操作预算必须明确。比较 fractional rectangle averaging 与 canonical resampling，勿假设后者必差。

Chase 以 |reliability| 排序，显式限制低置信位数量与翻转阶数；无观测为 erasure/低置信，不能当高置信 0。z-score 不是已校准的 bit 错误概率；有效观测数与离群值影响要保留诊断。

校验通过不是数学上零误报。对不同有效 payload 去重，记录搜索候选数；同一 payload 在多个相邻 scale 成功可视为一致证据。不同 payload 同时合法时输出 ambiguous，不能沿用首个 CRC 通过即返回。CRC 失败不得输出成功诊断字段；CRC 仅完整性自检，绝不标为验签。

建议输出 protocol、crcStatus、correctedBits、softRecovery、scale（API 对应 estimatedScale）、phase、pilot score/peak margin、candidateCount 和失败原因；具体 CLI/API 以实现文档为准，两端保持一致。

## 验证与交付

1. 协议/CRC/BCH/golden vectors：跨语言、0...6 位随机及边界错误，超限不保证恢复但不得未经校验报成功，整体奇偶位和非法字段测试。
2. canonical：PNG/JPEG/crop、v4 历史回归、两个 decoder 字段完全一致。
3. pilot/resize：0.5/0.6/0.75/0.793/0.8/0.9/0.917/1.1/1.25/1.5；不同裁剪形状、任意偏移、crop/resize/JPEG 不同顺序。记录 JPEG 编码器、4:2:0/4:4:4、重采样核。0.5× + 4:2:0 是压力测试。
4. 无水印 UI、普通照片、规则网格负样本：统计图片级误报率，不能只测正样本恢复率。
5. 记录成功与失败样本耗时/候选数、覆盖与零观测 bit、纠错次数；报告条件和样本数，不虚构速度提升或总体成功率。
6. 本地 swift build、swift test、python3 tools/test_bwdecode.py 与项目 CI。能运行则完成 Demo 构建/模拟器截图 E2E；真机、IM、人工可见性缺口如实列出。
